# Glossary - 多 Agent Profile Orchestrator

Living ubiquitous-language for the orchestrator. Each entry locks a concept the
spec or code otherwise overloads. Pre-existing terms (Feature Run, Lane, Agent
Profile, Stable IDs, Issue, Change Proposal) are defined in spec §5 / §17; this
glossary only locks terms the spec **overloads or leaves ambiguous**, with a
pointer to the ADR that established the lock.

| Term | One-line | Established |
| --- | --- | --- |
| **Decision** (artifact) | A cross-cutting, rationale-bearing engineering judgment, persisted as `decisions/DEC-NNN.{json,md}`. The unit of "judgment worth referencing later" (§2.4). Not a per-issue disposition, not a gate verdict. | ADR-0001 |
| **Disposition** (triage) | The Human-Triage verdict on one `ISSUE-NNN`: `accept \| reject \| defer \| override \| request_fix \| request_change_proposal` (§16). Lives as the `triage` state object on the issue, **not** as a Decision. Renamed from the spec's overloaded `"decision"` field. | ADR-0001 |
| **Verdict** | The pass/fail result a gate computes deterministically - e.g. `lane-decision.json` `verdict: pass\|fail` (§18.4, lane gate) and `feature-status.yml` `verdict` (§18.5, coherence gate). Renamed from the code/spec's overloaded `decision` / `final_verdict` fields. | ADR-0001, ADR-0003 |
| **Disarming** | Making a blocking issue (P0/P1) non-blocking, via `override` or `reject`. Always produces a Decision (proposed invariant #15). | ADR-0001 |
| **Invariant #5 (clarified)** | P0 cannot be waived by a mere reason; it can only be disarmed by a recorded Decision (`reject`-as-false-positive). The `override` disposition on P0 is forbidden entirely. (Spec §29 states only the letter - "P0 不可 override" - which this clarifies without contradicting.) | ADR-0001 |
| **Issue status** | Lifecycle state of an `ISSUE-NNN`: `raised \| triaged \| resolved \| reappeared`. Bookkeeping for the collector / fix-loop driver / `apply_triage`; the gate does **not** read it (it reads `severity` + `triage`). | ADR-0002 |
| **Fix-loop budget** | Feature-level `fix_loop_budget: {used, max: 1}`. The sole enforcer of §19's "at most one fix run" - `apply_triage` refuses `request_fix` once `used >= max`. Per implement-cycle (a CP resets it). | ADR-0002 |
| **Final report** | The terminal projection artifact: `final-report.json` (canonical, deterministic aggregation of issues/decisions/runs/audit/status answering §2.1's five questions) + `final-report.md` (skeleton rendered from the JSON). Persisted but re-computable; **not** a frozen artifact (§4.2 frozen set excludes it). v0.3 ships no narrative. | ADR-0003 |
| **failure_class** | Classification of a FAIL final report: `recoverable` (can unblock without changing frozen specs - e.g. pending CP fulfillment, pending triage) vs `terminal` (cannot reach pass in v0.3 - e.g. P0 rejected, `request_cp` recorded as FAIL). Carried in `final-report.json` `failure_class` + `blocking_reasons[]`. | ADR-0003 |
| **feature.status (derived)** | Not an independent field - a derived projection of `(current_gate, verdict)`: `planning` / `implementing` / `done` / `blocked`. Recomputed atomically whenever `current_gate` or `verdict` is written. `blocked` is coherence-fail only (lane-gate FAIL stays `implementing`). | ADR-0003 |
| **coherence-gate / final-report (commands)** | The two v0.3 deterministic commands mirroring §23.5 steps 20->21. `coherence-gate` is the audited canonical writer (`current_gate` + `verdict` + derived `feature.status`); `final-report` is a non-audited projection render that reads `verdict` and fail-loud refuses on null (§24.2). Split is contingent on the report staying non-canonical. | ADR-0003 |
| **origin** (audit) | The canonical driver tag on every audit event - *which* driver triggered it: `cli` (a direct primitive command), `implement-leg` / `review-leg` / `spec-gap-leg` (the agent legs), `fix-run-driver` (the `fix-run` bookend), `verifier` (the shell verifier), `dry-run`. A top-level record field (peer of `event`/`payload`), threaded in explicitly by the caller, never inferred. Locked here as the single name so it does not fragment into `actor`/`source`/`trigger`. The token value is never an origin and never enters the payload. | v0.4 ticket 02 |
| **elapsed_ms** (audit) | Payload convention for events with duration semantics (`run` / `verify` / `lane_gate` / `coherence_gate` / `fix_run`): wall-clock milliseconds from the event's `started` to its `ended` stamp. Events without duration semantics carry no `elapsed_ms` (its *absence* is meaningful, not a zero). Computed via `timeutil.elapsed_ms_between`. | v0.4 ticket 02 |
| **dry-run** | A `--dry-run` mode (ADR-0004) on the **side-effect** commands that runs the command's full planning + §24.2 precondition + legality check but skips the expensive/irreversible step (claude spawn for agent commands; canonical-state write for deterministic commands). **Invariant: dry-run never mints a stable id** - the would-be input package renders to a temp dir, not `runs/RUN-NNN`, so the `RUN`/`DEC` counters and the feature-run tree are untouched. Dry-run writes nothing (no canonical state, no audit append); a legality refusal is *reported* (`would be refused`), not raised, while a precondition breach still fails loud (exit 1). The `origin` audit field (ticket 02) has landed; the `origin=dry-run` *emission* itself remains deferred (ADR-0004 D4) - dry-run still writes nothing. | ADR-0004 |
| **Agent Profile** (disambiguated) | The orchestrator's §10 concept: *which* engine + model + auth runs an Agent Role (§9) - e.g. `cc-glm52`, `codex-default`. A record in `agent-profiles.yml`, dispatched on its `cli` field to an `AgentRunner` adapter (ADR-0005). **Not** codex's `-p/--profile` flag - that is a *codex config-file layer* (`$CODEX_HOME/<name>.config.toml`), an engine-internal knob exposed (if at all) as a `codex_config_profile` field, never called "profile" unqualified. The two share a word, not a concept. | ADR-0005 |
